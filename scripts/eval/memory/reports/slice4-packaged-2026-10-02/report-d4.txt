## Defects

1. **"Notes used in this answer" disappears the moment the transcript catches up, so a person never sees it (major for this surface).**
   - Mechanism:
     1. `done.memory_used` rides only on the *live* assistant row (`apps/openalpaca-gui/src/views/chat/transcript-model.ts:563`).
     2. `chat_stream_ended` invalidates the chat history (`lib/query-client.ts:143`).
     3. `showsLiveTurn` (`transcript-model.ts:375`) hides the live row as soon as a stored assistant row has the same content.
     4. A stored row always has `memoryUsed: []` (`:457`).
   - So the line exists for roughly one history round trip after `done`.
   - A scratch run of the real reducer and `buildTranscript` confirms it: memoryUsed counts are `[1]` before the refetch and `[0]` after (`track-d/repro-memused.ts`, output in `evidence/d4-repro-memused.txt`).
   - The tests never let history catch up: `transcript-model.test.ts`'s "rides on the live row once `done` lands" and `ChatView.test.tsx`'s "says which memory notes an answer used".
   - `docs/GUI_Manual.md:488` promises the line until a **reload**.
   - "Continuing from" survives because it is kept in its own state (`useChatSession.ts:499`, `:849`). `memory_used` could be held the same way.
   - The skipped-attachment note ("Not sent to the model", `transcript-model.ts:455`) has the same shape and very likely the same fault. That is **inferred, not exercised**.
2. **Layout: with the conversations column open in the 1080-pt window, the composer's Send button overflows its card.** It is drawn outside the composer border, over the column edge (`10-…`, `11-…`, `18-…`). The transcript column is about 150 pt wide at that point. Cosmetic.
3. **"1 notes"** (D3 defect 1) is seen again in `06-…` (`MemoryList.tsx:117`).
