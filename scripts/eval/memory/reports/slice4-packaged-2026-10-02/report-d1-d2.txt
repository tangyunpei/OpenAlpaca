## Concerns

1. **The spec and the map were absent.** `program/track-d/SPEC.md` and `program/maps/slices34.md` did not exist, and a search of `<tmp> found neither. The round-trip and the evidence set were rebuilt from the task text, plan 04 §2 *Gates* and §6, and 08 §4. That round-trip was add → list → search → show → forget, without `daemon stop`. The lead should check the verbs and the evidence names against the spec once it exists.
2. **The archive ships two different `openalpacad` builds** from the same commit:
   - `libexec/openalpacad` is `cdfef8e7…` (57,978,128 B), from `cargo build -p openalpaca -p openalpacad`.
   - The `.app`'s sidecar is `bdaa22a2…` (57,975,440 B), from `prepare-sidecar`'s `cargo build -p openalpacad`.

   Cargo feature unification compiles the shared crates differently for the two invocations. D2 tested the `.app`'s build only. This predates the branch and was not changed.
3. **The isolated store does not isolate `$HOME`.** At boot the daemon ran credential discovery: `TokenManager initialized with credential discovery` (`apps/openalpacad/src/services/llm.rs:178`). By default that reads `~/.claude/.credentials.json` and `~/.codex/auth.json` (`crates/openalpaca_llm/src/keys/credential_discovery/mod.rs:373`, `:424`). It also logged `Auto-detected Claude Code CLI at /opt/homebrew/bin/claude`, which is the CLI-backend fallback. I read none of those files.
   - Here nothing could leave the sandbox, and status shows no routable model.
   - For **D4**, the daemon reaches the real Ollama and is presumably not sandboxed. A failed model call could then fall through to the Claude Code CLI backend on the owner's account. The lead may want credential discovery and the CLI backend switched off in D4's scratch `llm.toml`. That is a decision; it was not applied here.
4. **For D3:**
   - The GUI must see the same `OPENALPACA_HOME_STORE` and `OPENALPACA_CONFIG_DIR`. `open -a` does not pass the environment unless `--env` is used; running `Contents/MacOS/openalpaca_gui` with the variables exported does. Otherwise the app looks at the default store, or spawns a sidecar of its own, unsandboxed.
   - The discovery token expires at **2026-10-04T04:03:29Z** (24 h, enforced by the clients).
   - The store holds no notes at hand-over, only the tombstone.
5. **`state/cache/` holds the index's WAL sidecars.** Besides `memory-index-v1.sqlite` it holds the same database's `-wal` and `-shm`. Plan §6's wording, "only `memory-index-v1.sqlite`", does not mention them. They are that one SQLite file's journal, not another artifact.
