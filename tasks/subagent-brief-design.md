### 0.3 The five upgrade rules (the lead's, from D1, L9 and S4)

- **U1 — Nothing a start did not write is changed.** No start writes, moves or deletes a file that exists under `config/`. The only writes in `config/` are the two empty directories `agents/` and `skills/`, when absent (§2.5).
- **U2 — A file the person edited always wins, and never silently gives way.** An edited file overrides the bundled entry of its id; one the daemon cannot parse holds its id as withheld (refused with the file's error), never the bundled entry in its place.
- **U3 — A file the person never edited stops hiding the bundle.** Byte-identical to a version OpenAlpaca shipped at that path, it is set aside at load — listed as not used, left on disk.
- **U4 — Every difference between disk and what runs is said.** At each start in `daemon.log`; on `GET /v1/agent-templates` and `GET /v1/skills`; in `openalpaca skills list` and `skills info`; in Settings → Agents. (`openalpaca agents list` and `agents status` read the `agent` table, which stores no provenance; they show every resolved template but not where it came from — §2.7 R-3.)
- **U5 — Every change is reversible by a file operation, live, and by going back a build.** Delete or move an override and the bundled entry is back without a restart (§2.4); start the earlier build and it reads `config/` exactly as it left it (§1.4).

## 1. The first start of the new build on an existing store

### 1.1 What an earlier build left behind

- Since `82022776` (L9, 2026-09-18) a first start writes the nine templates into `<config>/agents/` and the four skills (eight files, create-skill's four `.sh` at 0755) into `<config>/skills/`, each directory only when absent (`seed_default_content`, `apps/openalpacad/src/bootstrap/content.rs`). Nothing records what was written (no manifest, no stamp, nothing in `state/`).
- Before `82022776` an installed daemon had no templates or skills unless a person copied the repository's `config/` by hand — `content.rs`'s module doc: "The only cure was to copy the repository's `config/` by hand". Those copies were installation, not authorship.
- The repository has held **91 distinct versions** of the 17 files the bundle carries (68 template versions, 23 skill-file versions; measured with `git log -- <path>` and `git rev-parse <commit>:<path>` at `825a43e5`, unchanged at `cf1464ad`), **31** of them shipped by a seeding build (`82022776` and after): `system_agent.md` 3, `writing_agent.md` 3, `research_agent.md` 2, the other six templates 1 each; `create-skill/SKILL.md` 3, `check_exists.sh` 2, `list_skills.sh` 3, `scaffold.sh` 3, `write_skill_md.sh` 3, the other three `SKILL.md` 1 each. The other 60 reached a store only by a hand copy. The two `require_confirmation_for: ["file_delete"]` lines are in every `system_agent.md` from `9ed847fe` (2026-02-18), seven months before L9, to `eb98b820`; the first version, `6d231785` (2026-02-17), lists `file_delete` and `shell_execute`.
- Three fixes to shipped files never reached a seeded store and are hand steps today (`docs/Installation_Manual.md`, *Switching to the Markdown Memory Build*): step 7 (`system_agent.md`'s two `require_confirmation_for: ["file_delete"]` lines switch its approval prompts off — a safety fix, T34/F1, R30, `b79adc26`), step 8 (`writing_agent.md`'s `file_read`, storage design §15), step 9 (create-skill's scripts, N-SKILL-3, `189f733a`, `13f56c99`).
- In a development checkout the config directory **is** the repository's `config/` (`resolve_config_base_dir`, `apps/openalpacad/src/bootstrap/config.rs`), so every bundled file is also present as a config file, byte-identical to the current version.

### 1.3 What the person reads

- **`daemon.log`, at every start**, one summary per kind, then one line per override, warning or withheld id (examples with a store an earlier build seeded and the person edited `code_agent.md`):
  - `Agent templates: 9 bundled; 1 from /Users/x/.openalpaca/config/agents, overriding a bundled template (code_agent); 8 unedited copies of shipped versions set aside, not read (2 of them earlier versions: system_agent.md, writing_agent.md)`
  - `Agent template /Users/x/.openalpaca/config/agents/code_agent.md overrides the bundled template code_agent`
  - `Skills: 4 bundled (run from /Users/x/.openalpaca/state/cache/bundled-skills); 0 from …/config/skills; 4 unedited copies of shipped versions set aside, not read (1 of them an earlier version: create-skill)`
  - The texts are pinned by tests (§9); a summary is always `INFO`; an override is `INFO` (deliberate); a withheld id, a duplicate and §2.8's two warnings are `WARN`.
  - A plugin template refused because a bundled or file template holds its id is logged by the plugin manager's existing `WARN` — plugins start after the template summary (`PluginManager::start` runs after `services::initialize_services`) — and listed on the holder's row (`not_used`, `plugin_refused`).
- **The listings** carry the same facts per entry (§2.7); Settings → Agents shows a source chip and a "not used" line per row.
- **No event, no chat message.** A new `SystemEvent` variant needs a consumer (N-EVENT-1's re-add rule); the listings are the surface. Decided by: the lead.

### 1.4 Going back to the earlier build

- `config/` is untouched by the new build (U1), so the earlier build reads it exactly as before: its seeded copies, the person's edits. It ignores `state/cache/bundled-skills/` (it has never heard of it). An `llm.toml` that gained `[providers.<name>.model_aliases]` (§4.3) still loads: `ProviderConfig` (`crates/openalpaca_llm/src/config/llm_config/router_config.rs`) carries no `deny_unknown_fields`, so the earlier build ignores the key. The SA commits move no schema (migration 005 is not placed by step 3b), so the earlier build opens the database.
- **One case differs, and the Installation Manual says it (*Keep the builds apart*):** a store *first* started by the new build has an empty `agents/` and `skills/` (§2.5). An earlier build skips an existing directory (L9's gate, `root.exists()` in `seed_default_content`), finds no template and answers `no_lead_agent_message(true)` ("No agent templates are installed …"). Its cure is to delete the two empty folders; the next start of that build seeds them. This is the price of creating the directories (§2.5 S-1 says why it is paid).
- **A second case, of the person's making, is said with it:** the new build lists set-aside copies as safe to delete (§1.2). An earlier build skips an existing `agents/` or `skills/`, so a copy deleted under the new build is gone for it too — with `lead_agent.md` deleted it answers `no_lead_agent_message`, with `create-skill/` deleted it has no create-skill. The cure going back is the same: move `agents/` (or `skills/`) aside, and that build's next start seeds it again.
- Overrides the person wrote *for* the new build in its vocabulary (`model: inherit`, `model: fast`) are read by an earlier build as unknown model ids: unroutable, so the ladder substitutes, announced (`note_substitution`) — they degrade, they do not break.

### 1.5 A fresh install

No file is written into `agents/` or `skills/`; both are created empty. The bundled nine and four run. `llm.toml`, `daemon.toml`, `mcp.toml` and `tools/example.toml` are seeded as today. The store's `README.md` (written only when absent) describes `config/agents/` and `config/skills/` as the place for the person's own and overriding files and lists `state/cache/bundled-skills/` (§2.5 S-4).
